# save_repo_HVAC

Сохранить проект HVAC_CleanRoom_Project в локальный репозиторий (commit) и в удалённый (push на GitHub, `origin`, ветка `main`).

Корень проекта: `C:\Users\morfe\STM32CubeIDE\workspace_1.17.0\HVAC_CleanRoom_Project`. Оболочка — PowerShell, команды git выполнять из корня.

## Порядок

1. `git status --short` и `git branch -vv` — посмотреть изменения и текущую ветку. Если ветка не `main` — спросить пользователя, куда сохранять.
2. Проверить, что в коммит не попадёт лишнее:
   - сборки (`Debug/`, `Release/`, `*.elf`, `*.bin`, `*.hex`, `*.map`) — уже в `.gitignore`;
   - файлы с паролями, ключами, токенами (`.env`, `*.pem`, `credentials*`) — не добавлять, предупредить пользователя;
   - отдельные файлы больше 50 МБ — не добавлять, сообщить пользователю (GitHub их не примет).
3. `git add -A`.
4. Сообщение коммита — на английском, одной строкой, по сути изменений (посмотреть `git diff --cached --stat` и ключевые файлы). Если пользователь написал текст после команды — использовать его как сообщение.
5. `git commit -m "<сообщение>"`. Если изменений нет — коммит не делать, перейти к шагу 6 (могут быть неотправленные коммиты).
6. `git push origin main`.
   - Отказ из-за того, что на GitHub есть новые коммиты: `git pull --rebase origin main`, затем снова `git push origin main`. При конфликте — остановиться и сообщить пользователю, ничего не решать за него.
   - Никогда не использовать `--force`, не менять историю, не трогать настройки git.
7. `git status -sb` — убедиться, что ветка не впереди и не позади `origin/main`.

## Ответ пользователю

Коротко, по-русски, без команд и путей: сохранено локально и на GitHub (или что именно не получилось и почему), одна строка — что вошло в сохранение.
