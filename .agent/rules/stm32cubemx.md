# STM32CubeMX: инструкция пользователю

Если меняешь код в месте, которое **может затереть** генерация STM32CubeMX (вне `USER CODE BEGIN/END`, шаблонный stop/start, атрибуты задач, FreeRTOSConfig вне USER Defines, HAL callbacks вне USER блоков, Variable Definitions в ethernetif и т.п.):

1. Сначала по возможности клади правку в **USER CODE** или иной переживший Generate блок.
2. Если правка всё равно зависит от настроек MX / шаблона — **в том же ответе** выдай пользователю краткую инструкцию на русском:
   - что открыть в STM32CubeMX (дерево: Pinout & Configuration / Project Manager / Middleware...);
   - какие поля/галочки/числа выставить;
   - зачем (чтобы после Generate не стёрлось / не вернулся конфликт).
3. Не ограничивайся фразой «не правь вручную» / «пусть живёт шаблон» — пользователь код не пишет; нужна **пошаговая настройка MX**.
4. Приоритет при дубликатах с шаблоном MX: оставлять объявление/строку шаблона, адаптировать наш код под неё; инструкцию MX — если настройка в GUI реально существует.
