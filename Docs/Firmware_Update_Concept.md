# Обновление прошивок системы HVAC «одной кнопкой» — принцип и план

Дата: 2026-10-04. Статус: **принято**. Дополняет решения от 2026-10-02 (HANDOFF_HVAC.md, п. 5.4).

---

## 1. Коротко

- Каждый модуль один раз на заводе прошивается через ST-LINK **только загрузчиком**. Дальше все программы приходят по CAN от Главного ПЛК.
- **Главное хранилище прошивок — компьютер** (все версии и история). **На ПЛК — копия текущих версий** для каждого типа модуля (флеш W25Q128, 16 МБ).
- Порядок всегда такой: **сначала идентификация, потом обновление**.
- Новый или заменённый модуль ПЛК прошивает **сам**. Работающие модули — **только по команде человека**.
- Молчание модуля **никогда** не повод для прошивки — только авария «нет связи».
- Из OpenBLT берём **идеи**, не код (лицензия GPL). Загрузчик пишем свой.

---

## 2. Роли

| Кто | Что делает |
|---|---|
| Компьютер | Хранит все версии. Кнопка «Обновить» отправляет файл на ПЛК по Ethernet и даёт команду. Показывает журнал. |
| Главный ПЛК | Хранит копию текущих версий, ведёт перекличку модулей, решает, кого обновлять, раздаёт прошивки по CAN, ведёт журнал, показывает аварии на дисплее и в вебе. |
| Локомотив, HUB | Транзит кадров обновления между ПЛК и модулями на своей линии (позже — обновляются сами так же, как остальные модули). |
| Загрузчик модуля | Отвечает на перекличку, принимает и проверяет прошивку, запускает программу, защищает себя. |

---

## 3. Загрузчик модуля

1. **Память:** загрузчик в начале флеш, программа после него. Загрузчик защищает свою область и **никогда не стирает сам себя**.
2. **Данные модуля в загрузчике:** тип модуля (зашит при сборке, свой у каждого вида платы), тип платы (ревизия), UID чипа, версия загрузчика.
3. **Данные в файле прошивки (заголовок):** тип модуля, тип платы, версия, длина, контрольная сумма CRC32. Чужую прошивку загрузчик не принимает.
4. **При включении:**
   - короткое окно ожидания команды «обновись»;
   - проверка CRC программы: сходится — запуск программы; не сходится или программы нет — остаётся в загрузчике и сообщает «программы нет»;
   - счётчик неудачных запусков: если программа несколько раз подряд не дошла до нормальной работы (сторожевой таймер), модуль остаётся в загрузчике и сообщает об этом.
5. **Отвечает на перекличку сам загрузчик**, а не только программа — поэтому даже пустой или испорченный модуль виден ПЛК.
6. **Вход в режим прошивки из работающей программы** — только по особой команде с UID модуля и подтверждением. Случайная помеха такую команду не соберёт.

Состояния модуля: «нет программы», «программа работает», «программа есть, нужна другая версия», «программа не запускается».

---

## 4. Обмен при обновлении (идея из OpenBLT / XCP)

Последовательность команд от ПЛК к модулю (по его номеру/UID):

1. «Подключись» — модуль подтверждает, что в режиме прошивки, сообщает тип, плату, версию.
2. «Сотри область программы».
3. «Запиши кусок» — много раз; каждый кусок со своей контрольной суммой и номером, битый — посылается повторно.
4. «Проверь» — модуль считает CRC32 всей программы и сравнивает с заголовком.
5. «Запустись» — перезапуск; ПЛК при следующей перекличке проверяет, что версия стала новой.

## 5. Хранилище на ПЛК

- Для каждого типа модуля **два места**: «текущая» и «новая».
- Файл с компа пишется в «новую». «Текущая» в это время не трогается.
- ПЛК проверяет файл: CRC, тип модуля, тип платы, версию. Плохой файл отбрасывается, комп получает сообщение, всё остаётся как было.
- Хороший файл → ПЛК обновляет модули по одному.
- Все модули обновились → «новая» становится «текущей», старая остаётся **запасной для отката**.
- Обрыв при загрузке на ПЛК (Ethernet, питание) → старая копия цела, комп начинает заново.

### Конфигурация проекта (с 2026-10-05)

- Комп собирает из проекта файл конфигурации «HCFG» (`Shared_Libs/hvac_cfg.h`): заголовок 44 байта, модули по 8 байт (тип по каталогу, линия/рельс/место, число каналов), каналы по 8 байт (модуль, канал, сигнал, величина, диапазон ×0.1). До 8 КБ, 64 модуля, 256 каналов.
- `POST /api/cfg?size=&crc=` → ПЛК проверяет и пишет в W25Q, две копии по 16 КБ (0x0000 и 0x4000, заголовок «HCFS» пишется последним, при старте берётся новейшая целая). Каждая заливка — новое «поколение» (1..255). Прошивки лежат с 0x100000, не пересекаются.
- ПЛК рассылает каналы модулям: кадр 0x330 CFG_SET (ПЛК CAN1 → Loco CAN2 → Loco CAN1 → AI), ответ 0x331 CFG_STATUS (раз в 1 с и после каждого SET: тип, место, версия, поколение, маски ок/ошибка, код ошибки). Поколение модуля не совпало (перезапуск) → ПЛК шлёт снова; 5 попыток без ответа → ошибка «не подтвердил».
- Проверка цепочки: локомотив — по перекличке, AI — по CFG_STATUS, HUB — по состоянию шины CAN2; лишние модули на шине — ошибка. `GET /api/cfg/status` — итог (нет / работает / применяется / ошибки) и таблица модулей. Журнал: события 14 сохранена, 15 применена без ошибок, 16 ошибки, 17 повторная отправка.
- В приложении: раздел проекта «Выгрузка в ПЛК».

## 6. Контроль во время работы (перекличка)

1. Каждый модуль раз в несколько секунд сообщает: тип, UID, версия, состояние.
2. ПЛК помнит, какой UID стоит на каждом месте цепочки.
3. **Появился другой UID на месте → модуль заменили.**
   - пустой («программы нет») → ПЛК сразу прошивает текущей версией;
   - с программой другой версии → ПЛК обновляет (модуль только что поставлен и ещё ничем не управляет).
4. **У работающего модуля версия отличается** → ПЛК **не трогает**, показывает предупреждение на дисплее и в вебе; обновление — только по команде.
5. **Модуль замолчал** → авария «нет связи с модулем на месте N». Никакой прошивки.

### Защита от ложного запуска прошивки (помехи)

- Обновление запускается только по **явному** ответу модуля: «программы нет», «новый UID», «другая версия».
- Решение — только после **нескольких одинаковых** ответов подряд, каждый с правильной контрольной суммой.
- Нет ответа = нет обновления.
- Работающий модуль без команды человека не обновляется.

## 7. Аварийные ситуации, учитываемые в коде

| # | Ситуация | Поведение |
|---|---|---|
| 1 | Пропало питание модуля при прошивке | CRC не сходится → модуль в загрузчике «программы нет» → ПЛК прошивает заново |
| 2 | Обрыв CAN посреди передачи | Повтор куска несколько раз → прошивка модуля сначала → после N неудач авария «модуль не обновляется» |
| 3 | Испорченные данные | Контрольная сумма каждого куска и общая CRC32; битый кусок — повтор |
| 4 | Прошивка не для этого модуля | Загрузчик сверяет тип модуля и тип платы, чужую не принимает |
| 5 | Новая программа зависает | Сторожевой таймер → после нескольких неудачных запусков модуль остаётся в загрузчике → ПЛК возвращает запасную версию |
| 6 | Пропало питание ПЛК при приёме файла | Старая копия цела, комп начинает заново |
| 7 | Пропало питание ПЛК при раздаче | После включения перекличка показывает, кто без программы или со старой версией, обновление продолжается |
| 8 | Дубль номера / модуль не отвечает | Такой модуль не обновляется, авария на дисплее и в вебе |
| 9 | Попытка стереть загрузчик | Область загрузчика защищена, загрузчик себя не стирает |
| 10 | Обновление при работающем климате | Только по команде человека; выходы модуля на время обновления — в безопасное состояние |
| 11 | Прошивка старее текущей | По умолчанию запрещено; откат — только явной командой |

Всё пишется в **журнал ПЛК**: модуль (тип, UID, место), время, версия было/стало, результат.

---

## 8. Что берём из OpenBLT

Берём идеи: порядок команд (п. 4), CRC программы при каждом старте, окно ожидания при запуске, разделение памяти загрузчик/программа, ПЛК как посредник Ethernet → CAN.

Не берём код: лицензия GPLv3 (или платная). Нет переклички, автоматических номеров, замены модулей и хранения копий на ПЛК — это пишем сами.

## 9. План реализации

### Этап 1 — проверка без Ethernet (сейчас, Ethernet на текущей плате ПЛК не работает)

1. Общий протокол в `Shared_Libs`: кадры переклички и обновления, заголовок прошивки, CRC32. Сразу «боевой» формат.
2. Загрузчик для **одного** модуля (первый — AI или локомотив): перекличка, приём, проверка, запуск, защита себя.
3. Программа этого модуля собирается со смещением после загрузчика и с заголовком (тип, версия, CRC).
4. Модуль прошивается **загрузчиком** через ST-LINK.
5. Прошивка модуля **встраивается в прошивку ПЛК** при сборке; ПЛК прошивается через ST-LINK.
6. ПЛК при включении и во время работы ведёт перекличку и **сам** прошивает модуль, если программы нет или версия другая.
7. Результат — на дисплее и в отладчике CubeIDE: найденные модули, версии, счётчики, ошибки.
8. Проверка аварий: выдернуть питание и CAN во время прошивки, подсунуть чужую и битую прошивку, заменить модуль.

### Этап 2 — все модули

Загрузчики для остальных типов (общее ядро на каждый тип чипа), транзит через локомотив и HUB, обновление по одному, перекличка всей цепочки, журнал.

### Этап 3 — Ethernet и компьютер (новая плата ПЛК)

Хранилище на W25Q128 (два места на тип), приём файла по Ethernet, кнопка «Обновить» на компе / в веб-интерфейсе, откат, журнал в вебе, связь ID модулей с веб-конфигуратором.

Сделано (2026-10-05, ждёт проверки на железе): хранилище W25Q128 (текущая / новая / резервная на тип), приём файла по Ethernet, вкладка «Система → Прошивки» в приложении HVAC (файлы, отправка в ПЛК, модули на шине, запуск обновления с выбором «с другой версией» / «все», прогресс, остановка, журнал ПЛК), события ПЛК в журнале действий. Не сделано: откат на резервную по кнопке, связь ID модулей с веб-конфигуратором, обновление самого ПЛК.
